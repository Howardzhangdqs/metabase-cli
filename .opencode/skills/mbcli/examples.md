# mbcli Agent 测试任务样例

由浅入深 6 个任务，可直接复制到新会话（或 @mbcli 引用本 skill）逐个考验 Agent。

## T1 · 元数据探索（基础）
> "列出 quant_data 库里所有和期货(fut/futures)相关的表，附上每张表的描述和字段数，按表名排序输出 markdown 表格。"

考察：databases/tables --match、JSON 解析、结果重组。
通过标准：无幻觉表名；字段数与 `tables` 输出一致。

## T2 · 摸列取数（SQL 生成）
> "看看 tab_stock_price_daily 的字段，然后查出最近的 5 个交易日上证相关行情（不确定列含义就先 LIMIT 3 探测，别猜）。"

考察：fields 探测 → 谨慎写 SQL（显式 LIMIT）→ 信封解读。
通过标准：先探后查，无全表扫描；列名与实际一致。

## T3 · 资产复用（检索链路）
> "搜索现有卡片里有没有'消费'相关的，挑一张最相关的，显示它的 SQL，讲清楚它查了什么、能否直接复用到我的问题上。"

考察：search → cards show（pMBQL SQL 回显）→ 理解复述。
通过标准：SQL 原样回显不加戏；复述查询语义准确。

## T4 · Prompt 上下文生成（差异化能力）
> "为 bi_data 生成一份 schema 摘要，只要跟'用户活跃'相关的表，输出控制在 200 行以内，我要直接塞给另一个模型做数据问答。"

考察：context --table 组合 + --include-fields-pattern + 行数控制意识。
通过标准：产物可直接用作 system prompt，表/字段名零幻觉。

## T5 · 错误韧性（契约解读）
> "依次执行：查一个不存在的表；跑一条 `SELECT 1; DELETE FROM app_mau`；给个错误参数。每次解释退出码和 error.code，说明你下一步会怎么修正。"

考察：bad_query(1) / write_blocked(2) / invalid_args(2) 的正确归因与自愈。
通过标准：不把 exit 2 当服务端故障；能主动给出修正动作而非放弃。

## T6 · 端到端分析（综合）
> "'对比 app_mau 里最近两个月各渠道活跃度的变化'——自己决定看哪些表、验证哪些假设，最后给我一页结论。全程只读。"

考察：探索→假设→SQL→汇总的完整闭环 + 只读纪律。
通过标准：结论有数据支撑，查询均可复现（贴出用过的 SQL）。
